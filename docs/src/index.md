# PowerOpenAPIModels

Julia transport types for the Sienna power-system data model, generated from
[SiennaSchemas](https://github.com/Sienna-Platform/SiennaSchemas).

These packages are the **wire format**, not the data model. They describe what a Sienna
system looks like as JSON — every component, every association row, every unit annotation —
with no dependency on PowerSystems.jl or InfrastructureSystems.jl. That is what lets a
parser, a database, a service, or a language other than Julia exchange a system with Sienna
without linking against Sienna itself.

!!! warning "Pre-release"
    Every version below `1.0` is a pre-release. These packages can change incompatibly in
    any release, and no API stability is promised until `1.0`. Julia treats a bump in `x` of
    `0.x.y` as breaking, so a `[compat]` entry of `"0.1"` resolves within `0.1.*` — pin
    accordingly.

## The seven packages

Seven packages live in one repository, each registered separately so an application loads
only what it needs. The dependency chain is acyclic and each package owns one layer.

| Package | Owns | Depends on |
| --- | --- | --- |
| [`InfrastructureCoreOpenAPIModels`](packages/infrastructure_core.md) | Domain-neutral types, the model-type registry, the unit vocabulary, the `APIModel` supertypes | — |
| [`InfrastructureTimeSeriesOpenAPIModels`](packages/infrastructure_timeseries.md) | The six time series association types | InfrastructureCore |
| [`PowerCoreOpenAPIModels`](packages/power_core.md) | Power types shared across domains: topology, curves, costs, enums | InfrastructureCore |
| [`PowerOperationsOpenAPIModels`](packages/power_operations.md) | Branches, injections, services, outages, market structures | PowerCore |
| [`PowerInvestmentsOpenAPIModels`](packages/power_investments.md) | Technologies, financial data, policy requirements | PowerCore |
| [`PowerDynamicsOpenAPIModels`](packages/power_dynamics.md) | Dynamic machine, exciter, governor, and inverter models | PowerCore |
| [`PowerOpenAPIModels`](packages/umbrella.md) | Re-exports all six, plus `SystemDocument` and `PortfolioDocument` | all |

The two `Infrastructure*` packages must never gain a `Power*` dependency; the test suites
enforce it.

## Installation

```julia
using Pkg

# Everything, plus the document containers
Pkg.add("PowerOpenAPIModels")

# Or one domain only
Pkg.add("PowerOperationsOpenAPIModels")
```

## A first example

```@example quickstart
using PowerOpenAPIModels, JSON

bus = ACBus(;
    id = 1,
    number = 1,
    name = "bus1",
    available = true,
    bustype = ACBusType("REF"),
    base_voltage = 138.0,
    voltage_limits = MinMax(; min = 0.95, max = 1.05),
)

text = JSON.json(encode(bus))
```

```@example quickstart
back = decode(ACBus, JSON.parse(text))
back.voltage_limits
```

[The API](api.md) describes the whole surface: how a generated type is shaped, how encoding
and decoding work, how enums and discriminated unions are represented, how units are
declared, and how a whole document is assembled and validated.

## Regenerating

The Julia sources under each package's `src/` are generated by OpenAPI.jl's native Julia
generator from the SiennaSchemas bundles. A fix belongs in the schema or in the generator
configuration, never in the generated file — see the
[repository README](https://github.com/Sienna-Platform/PowerOpenAPIModels#readme).
